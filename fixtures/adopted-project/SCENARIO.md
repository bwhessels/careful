# Common fixture scenario

Ask the host to design and implement a public API change with a compatibility trade-off, then verify that Careful selected Deep work, requested/used evidence, assessed documentation impact, ran or reported independent review, and reported retrospective signals.

Have the first independent review return one material compatibility finding. After the finding is corrected, verify that the host does not claim clean closure until a fresh independent confirmation pass reports no material actionable findings. If that pass is unavailable or explicitly overridden, verify that the handoff instead records the missing pass, recovery path, and residual risk.

Record the host version, fresh-session proof, prompt, first review, correction, confirmation result, final response, and any degraded control in `evidence/<adapter>.md` before release.
