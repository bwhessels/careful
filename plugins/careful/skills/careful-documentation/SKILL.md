# Careful Documentation

Read `references/documentation-map.md`. Treat documentation as a routing and verification problem, not a request to write more Markdown.

1. Read the project documentation map when present. For an unknown project, use `careful-adopt` before creating a structure.
2. Assess whether the change affects behavior/specification, public contract/reference, architecture, a consequential decision, contributor workflow, operations, or orientation.
3. Update the canonical source once and link from other documents instead of restating facts.
4. For no-impact conclusions, state the relevant evidence in the final handoff.
5. Verify links, generated/reference outputs, and project documentation checks where available.
6. For Deep work, record the documentation impact assessment in the change evidence.
